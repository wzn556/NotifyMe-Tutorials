    Overview of small icons

    The small icon refers to the icon at 1 in the following figure:

    The small icon is controlled by the value iconType and smallIcon , which support the following usage:

    • Use the app's built-in notification icons;
    • Use notification icons added in Profiles/Small Icons/＋ (pre-added in application) ;
    • Use the network notification icons (set when sending a message) ;
    • Use notification icons imported in Profiles/Small Icons/Top Menu/Import Small Icons (pre-added in application) ;
    • Set the notification icon using the JSON(when sending the message).

    Set Specific Small Icons

    Use the Build-in Icons

    • Set iconType to any value of 0~5 when sending a message, smallIcon needn't to be set. example is as follows:

        "ttl": 86400,
        "priority": "normal",
        "data": {
            "title": "NotifyMe！",
            "body": "This is a test message!",
            "group": "Messages",
            "bigText": false,
            "iconType": 0,
            "smallIcon":"",
            "largeIcon":"largeIcon_0",
            "id":"0",
            "encryption":false,

    }
}

    Use Custom Icons

    Add with Pictures

    • Click Profiles/Small Icons/＋ to select the picture, then enter the name of the icon (for example Lena ) to complete to add the small icon.
    • Click the existing icon to remove it.

    [!CAUTION]

    Small icons added in this method are not in line with the Google specification. If your OS is AOSP (or based on AOSP) or icons do not work well(For example, the icon is completely white, or it is wrapped in other pattern, etc.), use either Batch Import or JSON Icons .

    • When sending a message, set iconType to 6 and set smallIcon to the name entered when importing the small icon (in the case of Lena ) .

    "data": {
        "to": "d-NnQPgQTYGF_JhRK6iFiB:APA91bET0S07sI1bOYBQ7FrWMBcQ53SyxnwO-ODXP19mDzku4ZijawFSQFT_LZ5cUqKPjDbd61-UBzzNiiiz_vkkYoK6jnu-zWU2qo1mDKYdy2wnjsZ99g_9j-vZ-5sm2QwNDWYAF_vh",
        "ttl": 86400,
        "priority": "normal",
        "data": {
            "title": "NotifyMe！",
            "body": "This is a test message!",
            "group": "Messages",
            "bigText": false,
            "iconType": 6,
            "smallIcon":"Lena",
            "largeIcon":"largeIcon_0",
            "id":"0",
            "encryption":false,
            "iv":"UkAjUPykxX1Eu4h7",
            "invisible":false,
            "actionType":"1",
            "action":"https://www.baidu.com",
            "channel":"quicker_channel"
        }
    }
}

    [!CAUTION]

    NotifyMe saves the image cache from the network when a URL is first used, which will lead to delay because of the time required to access the network. If the URL is used again, NotifyMe will get the image directly from the cache without any network access delays.

    If the image on the internet changed, click Profiles/Top Menu/Other Small Icons/Cached Icons to remove the icon (or through Menu/Clear Icons in the Cached Icons interface to remove all cached icons) and send a message again to make NotifyMe re-cache the icon.

    This method works in the same way as Add with Pictures and also does not comply with the Google specification. If you are using AOSP(or based on AOSP), or it doesn't work well(for example the icon is completely white, or it's wrapped in other pattern), use either Batch Import or JSON Icons.

    Use the Icon Library "AndroidNotifyIconAdapt"

    • The purpose of "AndroidNotifyIconAdapt" is to help Android non-standard APP and manufacturers adapt native notification icons, so that Chinese users can experience the beauty of standard native Android notification icons.

    • Project Address: AndroidNotifyIconAdapt | Github

    • Usage：

    Batch import icons via Profiles/Small Icons/Top Menu/Import Small Icons. You can copy the URL https://raw.githubusercontent.com/fankes/AndroidNotifyIconAdapt/main/APP/NotifyIconsSupportConfig.json into the textfield, click Ok to use it, or download the file and import it via From File.

    Refer to Import with the Sample File for specific invocation methods.

    [!IMPORTANT]

    Please respect the work of the original project author, @fankes , and be sure to state the references and sources of the original project in prominent places when reprinting.

    The JSON object has four keys(bitmap , color , name，and contributor). The icon mainly consists of bitmap and color. bitmap(white pattern at 2 in the figure) is the icon's pattern and should be pure white with a transparent background. color is the background color of the icon(bule background at 1 in the figure) , name is the name of the icon(at 3 in Figure)，contributor is the contributor of the icon.

    • The corresponding value for the key are as follows:

    bitmap：Icon bitmap data, convert PNG format images (size 72 × 72 or smaller, background transparent, white pattern) to Base64 strings for use. You can use the web tool Image to Base64 (lddgo.net) to complete conversion. Note to delete the previous string data:image/png;base64,.

    color：The background color of the icon, transparency is not required(transparency does not take effect).

    name： The name of the message icon. It is recommended to use the application package name as the name (for easily using application notifications forwarding) or the form Author.Work(for example, cuiliang.quicker).

    [!CAUTION]

    The bitmap should not be too large, or a Android message is too big error may occur when sending the message, and the recommended size is 72 × 72(can be slightly smaller, but not larger) . When there are too many details in the Image, the bitmap will also be too large even if the size is set to 72 × 72, the image should be compressed(loss of clarity), or use Image Trace in Illustrator to deal with the icon which can remove some of the details but keep the clarity). Oversize bitmap have no effect in Batch Import , but it is still recommended to reduce the bitmap volume.

    In some OSs(such as ColorOS), colorful bitmap can be displayed as a full color (no background color is shown), as shown below; but in AOSP(or based on AOSP), colorful bitmap is forced to be white. Other OSs may perform differently and can be tested for feedback for me to add here.
